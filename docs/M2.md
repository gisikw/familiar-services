# M2: singleton service cutover

`familiar-services serve --socket PATH --attention-db PATH --state-dir PATH`
owns Attention, worklist/DND, and wake timers. It listens on a mode-0600 Unix
socket. Each connection carries newline-delimited JSON. A request is
`{"op":"…","args":{…}}`; its response is either
`{"ok":true,"result":…}` or
`{"ok":false,"error":{"code":"invalid_request|not_found|conflict|unavailable","message":"…"}}`.
Requests and responses are each limited to 1 MiB. Clients may keep a connection
open and issue requests sequentially.

## Operations

| `op` | `args` | result / effect |
|---|---|---|
| `attn.project.list` | `hidden?` | projects (the `attn.` prefix may be omitted for compatibility) |
| `attn.project.get` | `slug` | project |
| `attn.project.add` | `slug, label?, default_policy?, repo?` | created project |
| `attn.project.set` | `slug, label?, default_policy?, repo?` | updated project |
| `attn.card.list` | `project?` or `lane?`; `owner?, edge?, q?` | concise cards |
| `attn.card.get` | `id` | full card |
| `attn.card.add` | `project, title, lane?, summary?, owner?, policy?` | full card |
| `attn.card.set` | `id, title?, summary?, owner?, policy?` | full card |
| `attn.card.move` | `id, lane` | full card |
| `attn.card.block` / `attn.card.unblock` | `id, reason` / `id` | full card |
| `attn.card.done` | `id, done?` | full jot card |
| `attn.note.add` | `card, text, detail?` | full card; author is Kes |
| `attn.evidence.add` | `card, kind, title, ref?, meta?` | full card |
| `attn.agent.start` | `card, name, model?, host?, harness?` | full card |
| `attn.agent.set` | `card, name, state, question?` | full card |
| `attn.jot.add` / `.list` / `.clear-done` | add: `title, owner?`; others: none | full jot / jots / archived count |
| `attn.status` | none | Attention counts |
| `worklist.list` | none | live items, oldest first |
| `worklist.enqueue` | `summary, id?, priority?, type?, body?, source?, suggested_deadline?` | `{item,created}`; stable IDs deduplicate against live and archived history |
| `worklist.ack` | `id` | delivered+acked item, moved to archive |
| `worklist.withdraw` | `id` | withdrawn item, moved to archive |
| `dnd.get` | none | active DND record or `null` |
| `dnd.set` | `enabled` (default true), `set_by?`, `duration_ms?` | DND record or `null`; Familiar setters are capped at two hours |
| `wake.schedule` | `mode, reason`, and `duration_minutes` or `fire_at` (epoch ms) | durable wake record |
| `wake.cancel` | `id` | `{cancelled}` |
| `wake.list` | none | pending wakes by fire time |

A due wake is claimed into `state/wakes/fired` before a priority-1 worklist item
with the wake ID is enqueued. Thus Pi remains the delivery path, but owns no
wake timer. `unless_wakened` wakes are cancelled when fresh work is enqueued.

## Cutover (no dual-writing)

1. **Freeze:** stop every resident Pi/extension and other process that writes
   Attention, `state/worklist`, or `state/wakes`. Keep delivery stopped. Make a
   backup while frozen (including SQLite `-wal`/`-shm` files if present).
2. **Switch:** point `--attention-db` at the existing `attention.sqlite` and
   `--state-dir` at the existing state parent. Start `familiar-services`, then
   verify `attn.status`, `worklist.list`, and `wake.list` through its socket.
   No import is needed: M2 deliberately reads the existing SQLite schema and
   file-store formats in place.
3. **Resume:** switch all clients to the socket, with the TypeScript stores and
   timers disabled, then restart Pi delivery. Never run old and new writers at
   once. Rollback means freeze again, stop the service, restore the backup only
   if needed, and re-enable the old writers.
